# 데이터와 모델 설명

## 데이터

- **이름**: UCI Bike Sharing Dataset — hour.csv
- **출처**: https://archive.ics.uci.edu/dataset/275/bike+sharing+dataset
- **라이선스**: CC BY 4.0 (재배포 가능, 출처 표기 필요)
- **기간**: 2011~2012년, Washington D.C. Capital Bikeshare
- **크기**: 17,379행 17열 (결측치·이상값 없음, 제거 0행)
- **SHA256**: `e03de4ee4ef4dc376ac6e04bf829673c6269e8eba5c60fa121640fa2f829504f`
- **확보 방법**: `make data`가 UCI 공식 zip을 내려받아 `hour.csv`만 꺼내고, SHA256이 위 값과 다르면 실패 처리한다. 저장소에는 데이터를 넣지 않는다.

## 데이터 한 건의 의미
`hour.csv`의 한 행은 **특정 날짜의 한 시간(예: 2012-03-23 17:00~18:00) 동안** Capital Bikeshare 전체 대여소에서 빌려간 자전거 수와, 그 시간의 달력·날씨 정보다.
- 입력: 그 시간의 달력 정보(계절, 월, 시간, 공휴일, 요일, 근무일)와 날씨(날씨 상태, 기온, 체감 기온, 습도, 풍속)
- 정답: 그 시간의 총 대여 수 `cnt` (단위: 대/시간)
- 서비스 요청 한 건도 같은 의미다. "이 조건의 한 시간 동안 몇 대가 대여될까?"

## 잘못된 값의 처리
| 단계 | 규칙 | 처리 | 이번 데이터 결과 |
|---|---|---|---|
| 데이터 파일 | SHA256이 고정값과 다름 | 실패 처리, 다음 단계 중단 | 일치 |
| 학습·평가 데이터 | 결측치가 있는 행 | 행 제거 (`src/data.py` `validate`) | 0행 |
| 〃 | 범위 밖 값: `temp`·`atemp`·`hum`·`windspeed` 0~1, `season` 1~4, `hr` 0~23, `mnth` 1~12, `weathersit` 1~4 | 행 제거, 제거 수를 로그에 남김 | 0행 |
| 서비스 입력 | 필드 누락, 정의되지 않은 필드(정답 `cnt` 등), 타입 오류(문자열, bool, 정수 필드의 소수), 범위 밖 | 예측하지 않고 `statusCode 400`과 오류 목록 반환 (`service/app.py`) | 테스트 6건으로 확인 |

## 입력 피처

| 피처 | 설명 | 타입 | 범위 |
|---|---|---|---|
| season | 계절 (1=겨울, 2=봄, 3=여름, 4=가을) ※ 아래 참고 | int | 1~4 |
| mnth | 월 | int | 1~12 |
| hr | 시간 | int | 0~23 |
| holiday | 공휴일 여부 | int | 0, 1 |
| weekday | 요일 (0=일요일) | int | 0~6 |
| workingday | 근무일 여부 | int | 0, 1 |
| weathersit | 날씨 상태 (1=맑음/구름 조금, 2=안개+흐림, 3=약한 눈/비·뇌우, 4=폭우/폭설·우박) | int | 1~4 |
| temp | 정규화된 기온 = 실제 기온(°C) ÷ 41 | float | 0~1 |
| atemp | 정규화된 체감 기온 = 체감 기온(°C) ÷ 50 | float | 0~1 |
| hum | 정규화된 습도 = 습도(%) ÷ 100 | float | 0~1 |
| windspeed | 정규화된 풍속 = 풍속(km/h) ÷ 67 | float | 0~1 |

### season 표기에 대한 주의
UCI 데이터셋 설명서(Readme.txt)에는 `1=봄, 2=여름, 3=가을, 4=겨울`로 적혀 있지만, 실제 `hour.csv` 값은 다르다.
`hour.csv`의 `dteday`(날짜)와 season 값을 직접 대조한 결과:

| season | 포함된 날짜 | 실제 의미 |
|---|---|---|
| 1 | 12/21 ~ 3/20 | 겨울 |
| 2 | 3/21 ~ 6/20 | 봄 |
| 3 | 6/21 ~ 9/22 | 여름 |
| 4 | 9/23 ~ 12/20 | 가을 |

따라서 이 프로젝트는 실제 데이터 기준(`1=겨울, 2=봄, 3=여름, 4=가을`)으로 표기한다.
모델은 숫자를 그대로 학습하므로 표기 차이가 예측에 영향을 주지는 않지만,
서비스에 입력하는 사람은 이 기준으로 값을 넣어야 한다.

## 제외 피처 (누수 방지)

| 피처 | 제외 이유 |
|---|---|
| casual | casual + registered = cnt (정답 누수) |
| registered | 위와 동일 |
| instant | 단순 행 번호, 의미 없음 |
| dteday | 날짜 문자열, hr/mnth 등에 이미 포함 |
| yr | 실험 결과: 평가 데이터에 yr=1만 존재해 학습 범위 밖 → 제외 |

## 출력

- **타겟**: `cnt` — 해당 시간의 실제 대여 대수 (대/시간)

시간 순서 기반 분할 (무작위 분할 금지 — 미래 데이터 누수 방지):

## 모델

- **종류**: `sklearn.ensemble.RandomForestRegressor`
- **하이퍼파라미터**: `n_estimators=200`, `random_state=42`, `n_jobs=-1`
- **저장**: `joblib` 압축 수준 3 (`config.yaml`의 `model.save_compress`), 약 26MB
  - 압축 없이 저장하면 148MB여서 Lambda 콜드 스타트 타임아웃이 발생했다 (`docs/incident.md` 오류 2)
- **버전(SHA256[:12])**: `0e16c92e1dd6` (scikit-learn 1.7.2, Python 3.14)

## 평가 방법

| 항목 | 내용 |
|---|---|
| 평가 자료 | 2012년(`yr=1`) 전체 **8,734건**. 학습에 쓰지 않은 미래 기간이다 |
| 비교 대상 (같은 평가 자료) | 베이스라인 ① 학습 데이터 `cnt` 전체 평균(143.8)을 항상 답함, ② 학습 데이터의 시간대(`hr`)별 평균을 답함 |
| 지표와 계산 | **MAE** = 평균(\|예측 − 정답\|), **RMSE** = √평균((예측 − 정답)²). 단위는 모두 대/시간. RMSE는 큰 오차에 더 민감하다 |
| 판단 기준 | ① 두 베이스라인보다 MAE·RMSE가 모두 낮으면 "입력 정보를 활용해 의미 있게 예측한다"고 본다. ② 운영 목적에 맞는지는 오차의 크기와 방향(과소/과대)으로 해석한다 |
| 평가 자료 사용 제한 | 모델 학습, 베이스라인 값 계산, 전처리 규칙(범위 기준)은 모두 학습 데이터나 고정 규칙으로만 정했다. 평가 자료는 지표 계산에만 썼다 |
| 서비스 정상 동작 검사 (별도) | 정상 입력 3건(→200)과 잘못된 입력 6건(→400)을 로컬(`make test`)과 클라우드(`make invoke`)에서 검사했다. 결과는 `docs/cloud.md` 5절 |
| 계산 코드 | `src/evaluate.py` → `results/metrics.json`, `results/error_analysis.md` |

## 평가 결과

| | MAE (대/시간) | RMSE (대/시간) |
|---|---|---|
| **RandomForest 모델** | **88.78** | **125.22** |
| 베이스라인 ② (hr별 평균) | 118.16 | 174.27 |
| 베이스라인 ① (전체 평균) | 168.25 | 227.81 |

**판단 기준 ① 충족**: 모델의 MAE가 hr별 베이스라인보다 25%, 전체 평균보다 47% 낮다.

## 결과의 의미 (해석)

평가 데이터에 대해 추가로 계산한 값이다.

| 지표 | 값 |
|---|---|
| 평가 데이터의 평균 대여량 | 234.7 대/시간 (학습 데이터 143.8의 1.6배) |
| 평균 오차 (예측 − 정답) | **−83.5 대/시간** |
| 실제보다 적게 예측한 비율 | **87.6%** |
| 오차 50대 이내 / 100대 이내 | 43.2% / 64.9% |

| 실제 대여량 구간 | 건수 | MAE | 평균 오차 |
|---|---|---|---|
| 0~100 | 2,927 | 14.3 | −5.2 |
| 100~300 | 3,102 | 71.6 | −66.1 |
| 300~600 | 2,057 | 159.7 | −158.6 |
| 600~1000 | 648 | 282.1 | −282.1 |

- MAE 88.78의 대부분(평균 오차 −83.5)은 **체계적인 과소 예측**이다. 2012년 이용량이 2011년보다 크게 늘었는데, 모델은 2011년 수준으로 예측한다.
- 수요가 많은 시간일수록 더 많이 모자라게 예측한다. 운영자가 그대로 쓰면 바쁜 시간에 **자전거를 덜 준비하게 된다**.
- 결론
  - 시간대·날씨에 따른 **상대적인 수요 패턴**(어느 시간이 바쁜지)은 베이스라인보다 잘 맞힌다.
  - **절대 대수**는 그대로 쓰기 어렵고, 최근 실적으로 재학습하거나 보정해야 운영 목적에 맞는다.
- 오차가 가장 큰 1건의 분석: [`results/error_analysis.md`](../results/error_analysis.md), [`results/error_analysis_notes.md`](../results/error_analysis_notes.md)

- 평가 기간이 2012년 한 해뿐이다. 다른 해나 특수 이벤트(대형 행사 등)에서의 성능은 확인하지 못했다.
- 측정하지 못한 부분: 동시 요청 부하. 지연 시간은 단건 호출로만 측정했다(`docs/cloud.md` 5절).
